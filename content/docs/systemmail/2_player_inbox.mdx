# 玩家收件箱

玩家使用以下任一命令打开收件箱：

```text
/systemmail
/smail
/mail
/sm
```

## 查找邮件

| 筛选  | 显示内容        |
|-----|-------------|
| 全部  | 当前仍可查看的全部邮件 |
| 未读  | 尚未打开详情的邮件   |
| 含附件 | 仍有附件可以领取的邮件 |

搜索会同时匹配邮件标题和发件人。打开详情后，邮件自动标记为已读。

## 领取附件

SystemMail 会先检查本次需要的全部背包空槽。空间不足时，整次领取直接拒绝，不会先发货币、
执行命令或只领取部分物品。

| 结果                  | 含义                   |
|---------------------|----------------------|
| `COMPLETED`         | 全部附件领取完成             |
| `INVENTORY_FULL`    | 背包空槽不足，任何附件都没有开始领取   |
| `NOTHING_CLAIMABLE` | 没有剩余附件可领             |
| `PLAYER_OFFLINE`    | 处理时玩家已经离线            |
| `EXPIRED`           | 邮件已过期，且当前界面没有有效宽限资格  |
| `QUARANTINED`       | 某项奖励结果无法自动确认，需要管理员处理 |


## 邮件到期时正在查看

默认情况下，如果玩家在邮件到期前已经成功打开详情，当前界面保留最多 20 分钟领取宽限。

- 切换邮件、关闭收件箱、退出服务器或重载 UI 后立即失效；
- 重复点击不会延长时间；
- 过期邮件不会重新出现在列表、搜索或未读数中；
- 其他插件通过公开 API 领取时不使用这段宽限。

服主可通过 `mail.yml -> limits.ui-claim-expiry-grace-minutes` 调整或关闭。

## 删除邮件

没有待领取附件的邮件可以直接删除。只要仍有未领取、处理中或等待管理员确认的附件，服务端就会拒绝删除，避免奖励丢失。

删除后的记录会保留一段时间供系统清理，天数由
`mail.yml -> retention.trashed-days` 控制。
