# 配置

主配置位于 `plugins/Ritual/config.yml`：

```yaml
timezone: "Asia/Shanghai"

rotation:
  anchor-monday: "auto"

delivery:
  check-interval-seconds: 20
  batch-size: 32
  processing-timeout-seconds: 30
  max-attempts: 50
  retry-delay-seconds: 2

history:
  cleanup-interval-hours: 12
  retention-weeks: 52
  audit-retention-days: 90
```

| 配置项                                   | 说明                                  |
|---------------------------------------|-------------------------------------|
| `timezone`                            | 每日零点和自然周使用的时区，例如 `Asia/Shanghai`    |
| `rotation.anchor-monday`              | 轮换第一组对应的周一；`auto` 会在首次计算周奖励时保存当周周一  |
| `delivery.check-interval-seconds`     | 扫描待发送奖励的间隔，范围 `1..300` 秒            |
| `delivery.batch-size`                 | 每批最多处理的奖励数，范围 `1..256`              |
| `delivery.processing-timeout-seconds` | 单次发放被占用后的超时，范围 `10..300` 秒          |
| `delivery.max-attempts`               | 连续失败达到多少次后暂停自动发送，范围 `1..10000` 次    |
| `delivery.retry-delay-seconds`        | 首次重试间隔，范围 `1..300` 秒；后续逐步延长，最长 1 小时 |
| `history.cleanup-interval-hours`      | 历史数据维护间隔，范围 `1..168` 小时             |
| `history.retention-weeks`             | 已完成签到、周分配和已送达记录的保留周数，范围 `8..520` 周  |
| `history.audit-retention-days`        | 签到、全勤和管理操作记录的保留天数，范围 `30..3650` 天   |

待发送和已经暂停的奖励不会被历史清理删除。

配置值超出表中范围时会被限制到最近的边界值。`config.yml` 不由 `/ritual reload` 重新读取；修改时区、轮换起点、投递或历史设置后，完整重启服务器。多节点部署时，应在各节点使用相同的时区和轮换起点。

## `language.yml`

`plugins/Ritual/language.yml` 管理玩家在签到界面中看到的业务结果，例如签到、全勤、投递状态和状态读取失败。唯一需要保留的消息占位符是全勤未达成提示中的 `{attendance}`：

```yaml
player:
  bonus:
    incomplete: "本周已签到 {attendance}/7 天，尚未达到全勤。"
```

修改后执行 `/ritual reload`。新文件校验失败时，插件继续使用原消息
