# 奖励组轮换

奖励组按服务器自然周统一轮换，不会根据玩家首次登录、首次签到或加入服务器的时间分别计算。同一周内所有玩家使用同一组奖励；共享 MySQL 的多个节点也使用同一个周分配。

只有已经启用的奖励组参与轮换，顺序以管理界面为准。假设启用了 A、B、C 三组：

| 周次    | 奖励组 |
|-------|-----|
| 第 1 周 | A   |
| 第 2 周 | B   |
| 第 3 周 | C   |
| 第 4 周 | A   |

关闭 B 后，轮换会改为 A、C。保存奖励、启停奖励组、调整顺序或删除奖励组时，本周会立即按照当前设置重新计算。

已经生成的邮件不会被修改或重复创建。配置变化只影响尚未生成邮件的领取。

## 轮换起点

`config.yml` 中的 `rotation.anchor-monday` 决定顺序中的第一组对应哪一周：

- `auto`：首次成功启动时，将当周周一保存为轮换起点；
- 明确日期：填写一个周一，例如 `2026-09-14`。

所有连接同一 MySQL 的节点必须使用相同的 `timezone` 和 `rotation.anchor-monday`，并保持系统时间同步。

如果所有奖励组都被关闭，玩家将无法签到。正式开放前至少保留一个已启用的奖励组。
