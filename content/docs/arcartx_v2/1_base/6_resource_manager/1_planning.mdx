## 架构建议

### 服务器分离

**资源更新服务器应与游戏服务器分开部署。** 游戏服务器带宽通常有限，若把资源分发也压在同一台机器上，会同时拖累游戏运行与资源下发的网络表现，整体效能下降。

### 成本与选型

资源分发的核心成本是**下行流量**：

- **对象存储（OSS）**：下行流量费用较高（市场参考价约 400–500 元 / TB），大规模分发成本会迅速攀升。
- **大带宽专用服务器**：性价比通常更高。常见的大带宽机型（如月租几十元、提供数百 Mbps 带宽并附带一定免费流量、超出部分按较低单价计费）更适合资源分发场景。

<Callout type="info">
具体服务商请自行评估选择，本文档不做推荐。
</Callout>

### 安全机制

后端采用**签名链接**向客户端分发资源，可对每条链接限制**下载次数**与**有效期**，并配合 **API 密钥 + IP 白名单**、**每日流量上限**、**频率限制**等手段，降低流量被盗刷的风险。

<Callout type="warn">
尽管后端内置了上述流量保护策略，**你仍需建立自己的流量监控与防护机制**（如服务器侧带宽告警、CDN / WAF、防火墙规则等）。普通玩家通常不会对你造成损失，但请警惕「友商」的恶意访问。
</Callout>

## 系统要求

- Linux x86_64（CentOS 7+ / Ubuntu 18.04+ / Debian 10+）
- 宝塔面板（推荐）或 systemd 环境
- 开放端口：`8080`（默认，可在配置中修改）
